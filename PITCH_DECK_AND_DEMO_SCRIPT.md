## Section 3: Defensible Judge Q&A Guide

### Q1: "Isn't eSAKSHI already doing this?"
> **Answer**: *"No. eSAKSHI is an excellent administrative workflow system — it manages proposals, sanctions, fund-flows, and photo uploads. However, eSAKSHI acts as a repository; it does not automatically compare submitted photos across districts to detect perceptual duplicate re-use, nor does it run multi-objective route optimization or compute Z-score cost anomalies against peer cohorts. Pratyaksh sits ON TOP of eSAKSHI as an intelligence layer to automate these audit insights."*

### Q2: "How do you avoid false accusations against officials or contractors?"
> **Answer**: *"We strictly enforce three system-level safeguards:
> 1. **Decoupled Scores**: Risk Score (0-100) measures statistical variance, while Verification Confidence (0-100) measures evidence presence. We NEVER merge them into a single 'guilt' score.
> 2. **Neutral Vocabulary**: Zero usage of words like 'fraud' or 'corrupt'. We use neutral labels like 'potential anomaly' or 'requires verification'.
> 3. **Role-Based Attribution**: Stage bottlenecks attribute delays to official roles (e.g. 'District Planning Officer IDA stage'), NEVER to individual named officials."*

### Q3: "Where does your data actually come from — is any of this real?"
> **Answer**: *"Yes! We ingested over 30,000 work records and 39,000 expenditure records from official public eSAKSHI and data.gov.in exports. For demonstration features that require private historical workflow event logs or duplicate image pairs, we generated realistic synthetic data. Every single record in our database and API explicitly tags its provenance metadata — `source_type` (`OFFICIAL_PUBLIC` vs `SYNTHETIC_DEMO`) and `is_synthetic` boolean — ensuring 100% data transparency."*

### Q4: "Can GPS coordinates or photos be faked by a corrupt agency?"
> **Answer**: *"Our Citizen Verification PWA strictly blocks gallery uploads — it forces a live HTML5 camera capture stream. Furthermore, the server independently calculates geodesic Haversine distance between the device's hardware GPS coordinates and the sanctioned project site. If a photo is uploaded from 1.4km away, the system flags a location discrepancy regardless of EXIF manipulation."*

### Q5: "Is this actually deployable, or just a hackathon demo?"
> **Answer**: *"It is fully deployable today! Our backend is containerized in Docker and configured for Render/Railway with a PostgreSQL + PostGIS database DDL. Our frontend is deployed on Vercel with native HTTPS support for browser camera and location APIs. We also include a complete offline local backup setup so the entire platform can run on a laptop without internet."*

### Q6: "What happens if the AI is wrong?"
> **Answer**: *"Every single score generated by Pratyaksh includes a clickable 'Why?' button that opens an immutable Audit Ledger entry. The ledger exposes the exact model version, rules version, named component breakdown, and data sources used. Most importantly, it includes an Officer Action feedback form allowing human officers to record field findings (`APPROVED`, `DISPATCHED`, `CLEARED`), ensuring the human stays in the loop."*

### Q7: "How would this integrate with government systems without replacing them?"
> **Answer**: *"Pratyaksh connects via standard REST APIs. eSAKSHI pushes project proposal JSON and photo URLs to our `/api/v1/risk` and `/api/v1/verification` endpoints. Our engines process the data asynchronously and return Risk Scores, Verification Confidence, and Inspection Priorities back to eSAKSHI dashboards via webhooks."*

### Q8: "What's your plan for scaling this nationwide?"
> **Answer**: *"Our architecture is built for horizontal scale:
> 1. **Stateless FastAPI Microservices**: Easily scalable across container clusters.
> 2. **PostgreSQL + PostGIS**: Efficient spatial indexing for millions of geographic coordinates.
> 3. **Perceptual Hashing**: pHash computes binary image fingerprints in milliseconds, allowing fast sub-second duplicate image lookup across nationwide image databases."*

### 2. Core Concept Cheatsheet (Must Know Without Hesitation)

- **Rule 1: Risk Score ≠ Verification Confidence**
  - *Risk Score*: Measures statistical deviation, financial variance, and SLA delay.
  - *Verification Confidence*: Measures multi-signal ground truth evidence (photos, citizen GPS, satellite).
  - *Never merge or average them into one number!*
- **Rule 2: Unavailable ≠ Suspicious (Fairness Safeguard)**
  - *Contradictory evidence (❌)*: Deducts points.
  - *Missing/Unavailable evidence (—)*: Isolated as missing, excluded from denominator, **returns 0.0 numerical penalty**.
